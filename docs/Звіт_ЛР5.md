## 2. АНАЛІЗ БІЗНЕС-ЛОГІКИ ТА ОБҐРУНТУВАННЯ МОДЕЛІ ДОСТУПУ

### 2.1. Аналіз архітектури системи LikedByGenre
Проєкт **LikedByGenre (SSS)** є веб-застосунком на платформі **ASP.NET Core 8 MVC**, що здійснює інтеграцію з сервісом **Spotify Web API**, завантаження вподобаних треків користувача (понад 2000 пісень), їх класифікацію за жанровими групами та автоматичний експорт сформованих списків у нові приватні плейлисти.

Система оперує як загальними системними даними (словник мапінгу жанрів, системна статистика), так і строго приватними користувацькими ресурсами (сесійні OAuth-токени Spotify, імпортовані треки бібліотеки, збережені експорти плейлистів, локальні облікові записи).

### 2.2. Порівняльний аналіз моделей доступу
1. **Дискреційна модель (DAC — Discretionary Access Control):**
   - *Суть:* Власник об'єкта або суб'єкт, що його створив, визначає права доступу до нього.
   - *Переваги:* Природно відображає концепцію персональної медіатеки та списку експортованих плейлистів (користувач володіє створеними ним плейлистами).
   - *Недоліки:* Не забезпечує централізованого системного адміністрування та аудиту.
2. **Мандатна модель (MAC — Mandatory Access Control):**
   - *Суть:* Доступ визначається мітками конфіденційності та рівнями допуску відповідно до суворої державної чи корпоративної політики (Bell-LaPadula, Biba).
   - *Висновок:* Надлишкова і непридатна для користувацького мультимедійного веб-сервісу.
3. **Рольова модель (RBAC — Role-Based Access Control):**
   - *Суть:* Права призначаються ролям, а користувачі отримують повноваження через належність до ролей.
   - *Переваги:* Спрощує керування загальними дозволами для типових груп користувачів (`Admin` та `User`).
   - *Недоліки:* У чистому вигляді не вирішує питання ізоляції приватних даних двох різних користувачів з однаковою роллю `User`.
4. **Атрибутна модель (ABAC — Attribute-Based Access Control):**
   - *Суть:* Рішення приймається на основі атрибутів суб'єкта, об'єкта, дії та середовища.

### 2.3. Обґрунтування вибору змішаної моделі (RBAC + DAC)
Для забезпечення максимальної безпеки, принципу мінімальних привілеїв (*Least Privilege*) та надійної ізоляції даних у системі реалізовано **змішану (комбіновану) модель доступу**, яка органічно поєднує:
- **RBAC (Role-Based Access Control):** Розмежування глобальних ролей `User` (звичайний клієнт системи) та `Admin` (адміністратор). Роль контролює допуск до адміністративної панелі, перегляду реєстру зареєстрованих користувачів, зміни ролей та системного моніторингу.
- **DAC (Discretionary / Ownership-Based Access Control):** Розмежування доступу до конкретних ресурсів бази даних на основі атрибута власності (`OwnerSpotifyId`). Користувач із роллю `User` має повний доступ (перегляд, імпорт, експорт, видалення) виключно до власних треків та плейлистів, але не може переглядати чи модифікувати ресурси інших користувачів.
- **Принцип Superuser в RBAC:** Адміністратор має повноваження аудиту над ресурсами системи для забезпечення технічного обслуговування.

### 3.3. Матриця правил доступу
Згідно з принципом заборони за замовчуванням (*Deny by Default*), доступ заборонено доти, доки явне правило не дозволить операцію:

| Ресурс / Операція | HTTP Endpoint | Anonymous | Role: User | Role: Admin | Застосований механізм | Правило перевірки |
|---|---|:---:|:---:|:---:|---|---|
| **Головна сторінка** | `GET /Home/Index` | ✅ | ✅ | ✅ | Публічний доступ | Відкрито для всіх |
| **Вхід / Реєстрація** | `GET/POST /Account/*` | ✅ | — | — | Публічний доступ | Дозволено для неавтентифікованих |
| **Spotify OAuth** | `GET /Account/ChallengeSpotify` | ✅ | ✅ | ✅ | Федеративна автентифікація | Ініціація PKCE OAuth конвеєра |
| **Власна бібліотека** | `GET /Library/Index` | ❌ (401) | ✅ | ✅ | RBAC + DAC | `[Authorize]` + фільтрація `Where(OwnerSpotifyId == CurrentUser)` |
| **Синхронізація треків** | `POST /Library/ImportTracks` | ❌ (401) | ✅ (свої) | ✅ | DAC | Доступ лише за власним токеном користувача |
| **Підтягування жанрів** | `POST /Library/ImportGenres` | ❌ (401) | ✅ (свої) | ✅ | DAC | Опрацювання артистів треків поточного користувача |
| **Огляд жанрів** | `GET /Genres/Index`, `/Details` | ❌ (401) | ✅ | ✅ | RBAC | `[Authorize]` на рівні контролера |
| **Створення плейлиста** | `POST /Playlists/Export` | ❌ (401) | ✅ (свої) | ✅ | DAC | Створення плейлиста в персональному Spotify акаунті |
| **Список плейлистів** | `GET /Playlists/Index` | ❌ (401) | ✅ (свої) | ✅ (всі) | DAC | Відображення записів виключно поточного власника |
| **Деталі плейлиста** | `GET /Playlists/Details/{id}` | ❌ (401) | ✅* | ✅ | **DAC (Безпосередня перевірка)** | `export.OwnerSpotifyId == CurrentUser` &rarr; інакше **403 Forbidden** |
| **Видалення експорту** | `POST /Playlists/Delete/{id}` | ❌ (401) | ✅* | ✅ | **DAC (Безпосередня перевірка)** | `export.OwnerSpotifyId == CurrentUser` &rarr; інакше **403 Forbidden** |
| **Панель адміна** | `GET /Admin/Index` | ❌ (401) | ❌ (403) | ✅ | **RBAC** | `[Authorize(Roles = "Admin")]` &rarr; редирект на `/Account/AccessDenied` |
| **Реєстр користувачів** | `GET /Admin/Users` | ❌ (401) | ❌ (403) | ✅ | **RBAC** | `[Authorize(Roles = "Admin")]` |
| **Керування ролями** | `POST /Admin/ChangeRole` | ❌ (401) | ❌ (403) | ✅ | **RBAC + Бізнес-правило** | Доступно тільки `Admin`. Заборонено понижувати останнього адміністратора |

\* *Операція дозволена виключно у разі збігу `OwnerSpotifyId` об'єкта з ідентифікатором поточного користувача.*

### 4.1. Модель користувача та конфігурація схеми бази даних
У сутність `User` додано поле `Role`, що зберігає призначену системну роль (`"Admin"` або `"User"`):

```csharp
// src/LikedByGenre/Models/User.cs
namespace LikedByGenre.Models;

public class User
{
    public int Id { get; set; }
    public string Username { get; set; } = string.Empty;
    public string PasswordHash { get; set; } = string.Empty;
    public string? SpotifyId { get; set; }

    /// <summary>
    /// Роль користувача для реалізації моделі RBAC ("Admin" або "User").
    /// </summary>
    public string Role { get; set; } = "User";

    public DateTime CreatedAt { get; set; } = DateTime.UtcNow;
}
```

У `AppDbContext.cs` налаштовано відповідність таблиці SQL Server:
```csharp
modelBuilder.Entity<User>(entity =>
```

### 4.2. Інтеграція ролей у механізм автентифікації (`AccountController.cs` та `Program.cs`)
Під час автентифікації користувача формується перелік `Claims`, куди обов'язково включається клейм типу `ClaimTypes.Role`:

```csharp
// AccountController.cs (метод Login POST)
var userRole = string.IsNullOrWhiteSpace(user.Role) ? "User" : user.Role;
var claims = new List<Claim>
{
    new(ClaimTypes.NameIdentifier, user.SpotifyId ?? user.Username),
    new(ClaimTypes.Name, user.Username),
    new(ClaimTypes.Role, userRole)
};

var identity = new ClaimsIdentity(claims, CookieAuthenticationDefaults.AuthenticationScheme);
var principal = new ClaimsPrincipal(identity);

await HttpContext.SignInAsync(
    CookieAuthenticationDefaults.AuthenticationScheme,
    principal,
    new AuthenticationProperties
    {
        IsPersistent = true,
        ExpiresUtc = DateTimeOffset.UtcNow.AddHours(8)
    });
```

Під час реєстрації реалізовано автоматичне призначення ролі `Admin` першому зареєстрованому користувачу системи:
```csharp
// AccountController.cs (метод Register POST)
var isFirstUser = !await _db.Users.AnyAsync();
var role = isFirstUser || normalizedUsername.Equals("admin", StringComparison.OrdinalIgnoreCase) ? "Admin" : "User";

var newUser = new User
{
    Username = normalizedUsername,
    PasswordHash = passwordHash,
    Role = role,
    CreatedAt = DateTime.UtcNow
};
_db.Users.Add(newUser);
await _db.SaveChangesAsync();
```

У `Program.cs` зареєстровано конфігурацію політик авторизації та сторінку відмови у доступі:
```csharp
builder.Services.AddAuthentication(...)
    .AddCookie(options =>
    {
        options.Cookie.Name = "LikedByGenre.Auth";
        options.Cookie.HttpOnly = true;
        options.LoginPath = "/Account/Login";
        options.AccessDeniedPath = "/Account/AccessDenied"; // Редирект при HTTP 403
        options.ExpireTimeSpan = TimeSpan.FromHours(8);
        options.SlidingExpiration = true;
    });

builder.Services.AddAuthorization(options =>
{
    options.AddPolicy("RequireAdmin", policy => policy.RequireRole("Admin"));
    options.AddPolicy("RequireUser", policy => policy.RequireRole("User", "Admin"));
});
```

### 4.3. Реалізація дискреційного контролю доступу (DAC — перевірка власності)
У відповідності до п. 8 завдання, **перевірка прав виконується безпосередньо у програмному коді перед здійсненням операції**, унеможливлюючи маніпуляцію через прямі HTTP-запити:

```csharp
// src/LikedByGenre/Controllers/PlaylistsController.cs

[Authorize]
public class PlaylistsController : Controller
{
    // ... інжекція сервісів AppDbContext, CurrentUser ...

    [HttpGet]
    public async Task<IActionResult> Details(int id, CancellationToken cancellationToken)
    {
        var export = await _db.PlaylistExports
            .Include(x => x.GenreGroup)
            .FirstOrDefaultAsync(x => x.Id == id, cancellationToken);

        if (export == null) return NotFound();

        var currentOwnerId = _user.SpotifyId;
        var isAdmin = User.IsInRole("Admin");

        // Безпосередня перевірка повноважень перед наданням доступу до ресурсу (DAC)
        if (export.OwnerSpotifyId != currentOwnerId && !isAdmin)
        {
            return Forbid(); // HTTP 403 Forbidden
        }

        return View(export);
    }

    [HttpPost]
    [ValidateAntiForgeryToken]
    public async Task<IActionResult> Delete(int id, CancellationToken cancellationToken)
    {
        var export = await _db.PlaylistExports
            .FirstOrDefaultAsync(x => x.Id == id, cancellationToken);

        if (export == null) return NotFound();

        var currentOwnerId = _user.SpotifyId;
        var isAdmin = User.IsInRole("Admin");

        // DAC: суб'єкт повинен бути власником об'єкта або володіти роллю Admin
        if (export.OwnerSpotifyId != currentOwnerId && !isAdmin)
        {
            return Forbid(); // HTTP 403 Forbidden
        }

        _db.PlaylistExports.Remove(export);
        await _db.SaveChangesAsync(cancellationToken);

        TempData["Status"] = $"Запис про експорт плейлиста «{export.Name}» видалено.";
        return RedirectToAction(nameof(Index));
    }
}
```

### 4.4. Реалізація контролера адміністрування (`AdminController.cs` — RBAC)
```csharp
// src/LikedByGenre/Controllers/AdminController.cs
namespace LikedByGenre.Controllers;

[Authorize(Roles = "Admin")]
public class AdminController : Controller
{
    private readonly AppDbContext _db;

    public AdminController(AppDbContext db) => _db = db;

    [HttpGet]
    public async Task<IActionResult> Index(CancellationToken cancellationToken)
    {
        ViewBag.TotalUsers = await _db.Users.CountAsync(cancellationToken);
        ViewBag.TotalTracks = await _db.Tracks.CountAsync(cancellationToken);
        ViewBag.TotalArtists = await _db.Artists.CountAsync(cancellationToken);
        ViewBag.TotalExports = await _db.PlaylistExports.CountAsync(cancellationToken);

        var recentUsers = await _db.Users
            .OrderByDescending(u => u.CreatedAt)
            .Take(10)
            .ToListAsync(cancellationToken);

        return View(recentUsers);
    }

    [HttpGet]
    public async Task<IActionResult> Users(CancellationToken cancellationToken)
    {
        var users = await _db.Users.OrderBy(u => u.Id).ToListAsync(cancellationToken);
        return View(users);
    }

    [HttpPost]
    [ValidateAntiForgeryToken]
    public async Task<IActionResult> ChangeRole(int id, string newRole, CancellationToken cancellationToken)
    {
        if (newRole != "Admin" && newRole != "User")
        {
            TempData["Error"] = "Неприпустиме значення ролі.";
            return RedirectToAction(nameof(Users));
        }

        var targetUser = await _db.Users.FindAsync(new object[] { id }, cancellationToken);
        if (targetUser == null) return NotFound();

        // Захист від втрати доступу: заборонено позбавляти прав єдиного адміністратора в системі
        if (targetUser.Role == "Admin" && newRole == "User")
        {
            var adminCount = await _db.Users.CountAsync(u => u.Role == "Admin", cancellationToken);
            if (adminCount <= 1)
            {
                TempData["Error"] = "Неможливо понизити роль єдиного адміністратора в системі.";
                return RedirectToAction(nameof(Users));
            }
        }

        targetUser.Role = newRole;
        await _db.SaveChangesAsync(cancellationToken);

        TempData["Status"] = $"Роль користувача «{targetUser.Username}» успішно змінено на «{newRole}».";
        return RedirectToAction(nameof(Users));
    }
}
```
