## 1. Призначення політики

Цей документ визначає правила створення, структуризації, оновлення та підтримки технічної документації програмного комплексу **LikedByGenre (SSS)**.

**Головний принцип:**
Документація є невід'ємною частиною кодової бази і має статус **Single Source of Truth** (єдиного джерела правди). Вона повинна відображати виключно фактичний стан реалізованого коду, моделей і конфігурацій. Застаріла, неповна або вигадана інформація вважається критичним дефектом проєкту.

## 3. Правила та вимоги до змісту документів

### 3.1. Заборона вигаданих технологій
У документації суворо заборонено згадувати або описувати технології, які фактично не використовуються в проєкті (наприклад: Redis, RabbitMQ, Kafka, Docker, Kubernetes, AWS, GraphQL, сторонні білінгові чи платіжні системи). Документація містить лише те, що присутнє у рішенні `LikedByGenre.sln`.

### 3.2. Формат специфікацій бізнес-логіки (`internal_spec/`)
Усі файли `business_logic.md` мають відповідати структурі шаблону:
1. **Purpose:** перелік обов'язків модуля та блок `NOT here` з явним зазначенням меж і суміжних модулів.
2. **Entities:** таблиця сутностей із полями, типами та переліком суворих **інваріантів** (саме інваріанти є головним змістом специфікації).
3. **Ключовий флоу:** покроковий опис основного процесу з визначенням меж (`Boundary`).
4. **Application Commands & Queries:** таблиці команд (`AC`) та запитів (`AQ`).
5. **Infrastructure:** технічні моделі EF Core, таблиці SQL Server та особливості роботи з API.

### 3.3. Формат політики безпеки (`policy/security_policy.md`)
Політика безпеки укладається за стандартом `Додаток А до ЛР№3` і містить усі 13 нормативних розділів, адаптованих під платформу ASP.NET Core 8 / SQL Server / Spotify OAuth 2.0 PKCE.

## 4. Процедура оновлення документації

- **Atomic Commits:** Будь-яка модифікація вихідного коду, яка змінює поведінку сервісів, структуру сутностей або конфігурацію, повинна супроводжуватися відповідними змінами у документації в рамках того самого завдання (коміту).
- **Changelog:** Будь-який реліз або суттєве оновлення функціоналу фіксується у файлі `docs/changelog.md` із зазначенням версії та дати.
- **Мова документації:** Основна мова технічної документації — українська. Назви технічних термінів, класів та бібліотек наводяться мовою оригіналу (C# / English).
