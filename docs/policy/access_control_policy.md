## 1. Обґрунтування вибору моделі керування доступом

Для веб-застосунку **LikedByGenre (SSS)** обрано **змішану (комбіновану) модель керування доступом**, яка поєднує:
1. **Рольову модель (RBAC — Role-Based Access Control):**  
   Розподіляє системні повноваження відповідно до ролі користувача (`User` або `Admin`). Відповідає за загальний допуск до підсистем та функцій адміністрування (перегляд реєстру користувачів, зміна ролей, загальна статистика системи).
2. **Дискреційну модель (DAC — Discretionary / Ownership-Based Access Control):**  
   Визначає правила доступу до приватних об'єктів медіатеки та експортованих плейлистів на основі власності (`OwnerSpotifyId`). Користувач із роллю `User` володіє повними правами на свої власні сутності (перегляд, імпорт, експорт, видалення), але не має жодного доступу до чужих сутностей. Адміністратор (`Admin`) виступає як суперкористувач і може здійснювати аудит та обслуговування.

### Чому не обрано інші моделі окремо?
- **Лише RBAC:** Не дозволяє вирішити проблему ізоляції даних між різними звичайними користувачами, оскільки всі вони мають однакову роль `User`, проте не повинні бачити чи видаляти чужі плейлисти.
- **Лише DAC:** Ускладнює системне адміністрування, моніторинг та керування обліковими записами без концепції привілейованих ролей.
- **Мандатна модель (MAC):** Надлишкова та не відповідає специфіці музичного веб-сервісу, де немає грифів таємності чи державних рівнів допуску.

## 2. Суб'єкти, об'єкти та їхні атрибути

### 2.1. Суб'єкти системи
| Суб'єкт | Опис | Атрибути суб'єкта |
|---|---|---|
| **Гість (Anonymous)** | Неавтентифікований відвідувач веб-сайту | `IsAuthenticated = false` |
| **Користувач (User)** | Автентифікований звичайний користувач | `IsAuthenticated = true`, `Role = "User"`, `UserId`, `SpotifyId`, `Name` |
| **Адміністратор (Admin)** | Автентифікований адміністратор системи | `IsAuthenticated = true`, `Role = "Admin"`, `UserId`, `SpotifyId`, `Name` |

### 2.2. Об'єкти системи
| Об'єкт | Сутність у моделі | Атрибути об'єкта |
|---|---|---|
| **Трек бібліотеки** | `Track` | `Id`, `SpotifyId`, `OwnerSpotifyId`, `Name`, `AlbumName` |
| **Експорт плейлиста** | `PlaylistExport` | `Id`, `SpotifyPlaylistId`, `OwnerSpotifyId`, `Name`, `TrackCount`, `CreatedAt` |
| **Група жанрів / Словник** | `GenreGroup`, `GenreMapping` | `Id`, `Name`, `Slug`, `SpotifyGenre` |
| **Обліковий запис користувача** | `User` | `Id`, `Username`, `PasswordHash`, `Role`, `SpotifyId`, `CreatedAt` |
| **Системна статистика / Аудит** | View Models / DB Aggr. | Кількість користувачів, загальна кількість треків, системні логи |

## 3. Матриця та правила розмежування доступу

| Операція / Ресурс | Anonymous | Role: User | Role: Admin | Тип контролю | Правило перевірки доступу |
|---|:---:|:---:|:---:|:---:|---|
| **Перегляд Home (`/`)** | ✅ | ✅ | ✅ | Публічний | Дозволено всім |
| **Реєстрація / Вхід (`/Account/*`)** | ✅ | — | — | Публічний | Дозволено всім неавтентифікованим |
| **Перегляд власної бібліотеки (`/Library`)** | ❌ (401) | ✅ | ✅ | RBAC + DAC | Потрібна автентифікація; вибірка `WHERE OwnerSpotifyId == CurrentUser.SpotifyId` |
| **Синхронізація треків Spotify** | ❌ (401) | ✅ | ✅ | DAC | Дозволено тільки для власного Spotify-токену поточного користувача |
| **Підтягування жанрів артистів** | ❌ (401) | ✅ | ✅ | DAC | Дозволено тільки для артистів із треків поточного користувача |
| **Перегляд жанрових груп (`/Genres`)** | ❌ (401) | ✅ | ✅ | RBAC | Вимагає автентифікованого сеансу (`[Authorize]`) |
| **Експорт плейлиста (`Playlists/Export`)** | ❌ (401) | ✅ | ✅ | DAC | Створення плейлиста в особистому Spotify акаунті суб'єкта |
| **Перегляд списку експортів (`Playlists/Index`)** | ❌ (401) | ✅ (свої) | ✅ (всі) | DAC | Звичайний користувач бачить виключно записи із своїм `OwnerSpotifyId` |
| **Деталі експорту (`Playlists/Details/{id}`)** | ❌ (401) | ✅* | ✅ | DAC | **Захищена операція:** якщо `export.OwnerSpotifyId != currentSpotifyId` та користувач не `Admin` &rarr; **403 Forbidden** |
| **Видалення експорту (`Playlists/Delete/{id}`)** | ❌ (401) | ✅* | ✅ | DAC | **Захищена операція:** видалити об'єкт може лише його безпосередній власник або `Admin` &rarr; інакше **403 Forbidden** |
| **Панель адміністрування (`/Admin/Index`)** | ❌ (401) | ❌ (403) | ✅ | RBAC | `[Authorize(Roles = "Admin")]` &rarr; при відсутності ролі HTTP 403 / AccessDenied |
| **Реєстр користувачів (`/Admin/Users`)** | ❌ (401) | ❌ (403) | ✅ | RBAC | `[Authorize(Roles = "Admin")]` |
| **Зміна ролей (`/Admin/ChangeRole`)** | ❌ (401) | ❌ (403) | ✅ | RBAC | Дозволено тільки `Admin`. Заборонено позбавляти ролі єдиного адміністратора в системі |

## 4. Точки та механізм виконання перевірок

Згідно з вимогами стандарту безпеки та п. 8 ЛР№5, **перевірка прав виконується безпосередньо у програмній логіці перед виконанням операції**, а не лише приховуванням кнопок в інтерфейсі користувача:

1. **Рівень маршрутизації та фільтрів ASP.NET Core (RBAC):**
   - Декларативний фільтр `[Authorize]` на рівні контролерів (`LibraryController`, `PlaylistsController`, `GenresController`).
   - Фільтр `[Authorize(Roles = "Admin")]` на рівні `AdminController`.
   - Запит від суб'єкта без відповідної ролі автоматично зупиняється конвеєром обробки запиту (Authorization Middleware) і повертає статус HTTP 403 Forbidden із перенаправленням на `/Account/AccessDenied`.
2. **Рівень бізнес-логіки дій контролера (DAC):**
   - У методах `PlaylistsController.Details(id)` та `PlaylistsController.Delete(id)` сутність спочатку вибирається з бази даних, після чого перевіряється умова власності:
     ```csharp
     if (export.OwnerSpotifyId != currentOwnerId && !User.IsInRole("Admin"))
     {
         return Forbid(); // Негайне повернення HTTP 403 Forbidden
     }
     ```
   - Навіть якщо зловмисник відправить прямий POST-запит через Postman чи curl із підробленим `id` чужого плейлиста, операцію буде заблоковано.
3. **Рівень доступу до даних (EF Core Data Access Layer):**
   - Усі сервіси `LibraryImportService` та `PlaylistExportService` примусово додають предикат `Where(x => x.OwnerSpotifyId == _user.SpotifyId)`.
4. **Рівень користувацького інтерфейсу (UI Presentation Layer):**
   - Кнопки адміністративних панелей та чутливих дій відображаються умовним рендерингом (`@if (User.IsInRole("Admin"))`), що запобігає ненавмисним діям, але не замінює серверну авторизацію.

## 5. Обробка відмов у доступі
- **Неавтентифікований доступ:** Редирект на `/Account/Login` із параметром `ReturnUrl`.
- **Порушення політики RBAC (недостатньо прав):** HTTP 403 Forbidden із редиректом на спеціалізовану інформативну сторінку `/Account/AccessDenied`.
- **Порушення політики DAC (спроба маніпуляції чужим об'єктом):** `ForbidResult` (HTTP 403 Forbidden).
