# ====== Playlists BUSINESS LOGIC ======

> Специфікація концептуального змісту модуля `Playlists` відповідно до шаблону ЛР№2. Модуль відповідає за створення приватних плейлистів у Spotify-акаунті та наповнення їх піснями відповідного жанру.

## Purpose

`Playlists` володіє:
- формуванням нових приватних плейлистів у профілі поточного користувача через Spotify Web API;
- пакетним завантаженням (batching) треків обраного жанру до створеного плейлиста;
- реєстрацією та збереженням історії виконаних експортів (`PlaylistExport`) у локальній базі даних;
- наданням списку попередніх експортів для відображення в інтерфейсі.

**NOT here:**
- авторизація користувача та оновлення токенів — `Identity`;
- локальне збереження вподобаних треків — `Library`;
- алгоритм розподілу треків за жанровими групами — `Classification`;
- видалення або перейменування раніше створених плейлистів у Spotify (модуль лише створює нові плейлисти).

## Entities

| Entity | Basic Fields | Description | Invariants |
|---|---|---|---|
| `PlaylistExport` *(Aggregate Root)* | Id, OwnerSpotifyId, GenreGroupId, SpotifyPlaylistId, Name, TrackCount, CreatedAt | Запис про успішно створений та наповнений плейлист у Spotify. | - `OwnerSpotifyId` обов'язковий і відповідає поточному користувачу.<br>- `SpotifyPlaylistId` — непорожній рядок, виданий Spotify API.<br>- `TrackCount` строго > 0.<br>- `CreatedAt` фіксується у форматі UTC у момент успішного завершення експорту.<br>- Ідентичність та поля запису після створення є незмінними (іммутабельний журнал експорту). |

## Ключовий флоу: Експорт жанрового плейлиста

1. Користувач надсилає команду експорту із зазначенням `slug` обраної жанрової групи (`POST /Playlists/Export`).
2. Модуль звертається до `Classification` для отримання об'єкта `GenreGroup` та перевірки наявності треків:
   - Якщо група не знайдена або кількість треків дорівнює 0 — операція переривається з помилкою.
3. Отримання актуального Bearer access-токена з `Identity` (`_user.GetAccessTokenAsync()`).
4. Формування назви плейлиста за шаблоном: `Liked · {group.Name}`.
5. Виклик `POST /v1/me/playlists` через `SpotifyApiClient`:
   - Створюється приватний плейлист (`@public = false`) з дескрипшеном: `"Плейлист зібрано з лайкнутих пісень додатком LikedByGenre."`.
   - Отримується згенерований `SpotifyPlaylistId`.
6. Пакетне додавання треків у плейлист (`POST /v1/playlists/{id}/items`):
   - Оскільки Spotify API обмежує кількість елементів у запиті до 100 одиниць, список URI розбивається на чанки по 100 елементів (`uris.Chunk(100)`).
   - Кожен пакет послідовно передається до Spotify із повторними спробами у разі отримання статусу 429.
7. Створення екземпляра `PlaylistExport` із метаданими операції.
8. Збереження запису в локальну базу даних SQL Server через `AppDbContext`.

**Boundary:** Створення плейлиста та HTTP-запити — `Infrastructure` / `SpotifyApiClient`. Формування списку URI та назви — `Playlists`.

## Domain Services

Кожен сервіс виконує чітку операцію:

| Domain Service / Method | Operation |
|---|---|
| `PlaylistExportService.ExportGroupAsync` | Повний оркестрований процес створення плейлиста, пакетного наповнення треками та збереження запису аудиту в БД. |
| `PlaylistExportService.GetExportsAsync` | Вибірка історії експортів, здійснених поточним користувачем, відсортована від найновіших. |

## Application Commands & Queries

**Commands (`AC`):**

| Area | Commands |
|---|---|
| Експорт | `ExportGroupAC` (приймає `slug` групи жанру, створює плейлист у Spotify та запис у базі) |

**Queries (`AQ`):**

| Query | Purpose |
|---|---|
| `GetExportsAQ` | Отримання списку експортованих плейлистів для відображення на сторінці `/Playlists`. |

## Infrastructure

### Models

- `PlaylistExports` — таблиця в базі даних SQL Server (EF Core).
- Зв'язок із `GenreGroup` реалізований через зовнішній ключ `GenreGroupId`.
- Жодні персональні токени чи секрети не записуються в таблицю `PlaylistExports`.
